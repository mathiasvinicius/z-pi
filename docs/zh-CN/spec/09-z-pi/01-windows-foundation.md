# Z-PI Windows 基础配置（分支差异）

> **翻译说明：** 本页对应 [英文源规格](/spec/09-z-pi/01-windows-foundation)。如有歧义，以英文版本为准。

本页只记录 Z-PI 相对于上游 PI-Desktop 的差异；其他行为仍由现有规格定义。

## 当前实现

- Windows 便携版根据原始可执行文件的位置，将 `.pi-desktop` 放在其旁边，而不是放在临时解压目录或用户主目录。Electron 的 `userData` 和单实例锁也位于该配置目录。显式测试覆盖仍然有效。现有打包器仍将应用程序二进制文件解压到临时目录；当前修改只迁移配置数据。
- 便携配置的全局 Agent 指令位于 `<profile>/agent/AGENTS.md`；项目指令仍位于项目内。全局 skills 使用便携配置目录。非便携安装保持原有路径，直到明确设计迁移方案。
- 新配置默认使用 pt-BR。用户明确设置的语言和跟随系统语言的 `auto` 选项保持有效。
- Windows 默认不再绑定 Alt+Space 全局插件启动器；用户仍可自行设置启动器快捷键。
- Windows 产品名称为 Z-PI，更新源指向 `mathiasvinicius/z-pi`。便携版暂时只显示手动更新链接，不运行 NSIS 安装程序。由于便携包缺少 `app-update.yml`，手动检查会直接配置此分支的 GitHub 更新源；已保存的自动更新偏好也不能在便携版或 ZIP 版启用 NSIS。尚未实现便携版可执行文件的自动替换。
- 渲染页面的 HTML 标题为 Z-PI，与原生窗口标题一致。
- ZRouter 已加入可选服务预设，地址为 `https://zrouter.itms.com.br/v1`。全新数据库会记录一次性的待配置标记；首次启动且尚无服务时，界面直接打开该预设表单。用户必须输入密钥，之后才通过现有的按密钥发现模型及加密保存流程。应用不会自动创建服务或密钥。旧数据库没有此标记；创建任一服务后标记完成。
- 首次准备 Chromium 状态时，便携版配置目录会被设置为 Windows 隐藏目录；这不是访问控制。当前尚未在可执行文件旁创建 `app` 目录。
- 语义 skills 解析器作为内置插件随应用提供，只向插件提示词贡献一份路由指令。每次查询都会重新扫描本配置目录中的 Markdown skills，不会移动或覆盖已有文件；同一 ID 的本地文件优先于插件库副本。学习到的步骤保存在当前配置目录的插件数据中。解析器也会以只读方式发现一级 `<name>/SKILL.md` 目录包；搜索时不会载入包内资源。
- 当语义路由器已加载且在项目中启用时，Electron 主进程仅隐藏路由器在此配置目录中确实可发现的重复全局 skill 元数据。链接、超大、不支持的格式、项目级以及其他根目录的 skills 仍留在原生目录中。host-core 的所有权和按需直接读取 `Skill` 的能力不变。

## 后续工作

- 第一版未签名的 Windows 便携包已在干净的临时目录中启动，窗口、host-core、sidecar 和内置语义插件均已就绪。更新后的便携包显示了 Z-PI 窗口标题，并访问了目前尚无正式发布版本的分支 GitHub 更新源。两个临时副本也能同时打开，分别使用独立的配置目录；重复启动同一副本不会再开新窗口。最新便携包的干净启动也不再出现 `app-update.yml` 警告。仍须验证内容和凭据隔离以及完整的首次使用流程。
- 决定是否需要将应用程序解压到 `<exe-directory>/app`，再宣称所有运行文件都位于便携根目录。
- 设计最小权限的用户数据访问控制和非破坏性升级后，实现 `%ProgramData%/ITMS/Z-PI` 的 `--install`。
- 将来若便携布局创建 `<exe-directory>/app`，也要隐藏新建目录，不隐藏无关的既有目录。
- 实现带完整性校验、进程退出后替换和失败回滚的便携版自动更新。
- 使用本地模型发现模拟服务，在打包应用中验证 ZRouter 首次配置；补齐密钥验证、离线行为、可编辑模型别名，以及获准工具对凭据的自动使用，同时不得泄露密钥。
- 完成项目级语义发现与原生目录整合。当前可见性策略只去除已确认的配置目录级重复内容；插件尚未搜索项目 skills。正式发布前仍需在打包应用中验证插件工具调用和选择。

另见仓库根目录的 `requerimentos.md` 与架构决策 `docs/adr/z-pi-windows-profile-and-release.md`。
